# 图片、视频与内容来源核验

媒体核验至少包含四个不同问题，不能合并成“真图/假图”：

1. 文件或帖子最早从哪里出现；
2. 文件是否被编辑、重编码或生成；
3. 画面、声音或文字实际呈现了什么；
4. 发布者对画面的事件、地点、时间和意义的描述是否正确。

## 1. 拆分声明

例如“这是 2026 年 A 城洪灾的 AI 假图”应拆成：

- 该文件首次可追踪出现的时间与账号；
- 它是否包含生成或编辑证据；
- 画面地点是否为 A 城；
- 画面时间是否为 2026 年指定洪灾；
- 它是否被错误配文或旧图新用。

即使确认图片经过生成或编辑，也不自动证明配文中的事件没有发生；反之，真实相机拍摄的旧图也可能被用于虚假叙事。

## 2. 建议顺序

1. 保存原始 URL、帖子时间、账号和可获得的最高质量文件。
2. 查找更早版本、原始发布者和传播链。
3. 对图片做反向搜索；对视频提取关键帧分别搜索。
4. 比较建筑、路牌、天气、阴影、地形、车辆、语言和已知现场素材。
5. 检查元数据、编码信息、水印和可验证的内容凭证。
6. 查找当事机构、现场人员、权威记录和独立报道。
7. 将文件来源结论与画面事实结论分开输出。

## 3. C2PA 与内容凭证

内容凭证可以帮助确认：

- manifest 是否存在并能被解析；
- manifest 与当前资产的绑定是否有效；
- 签名、证书链、吊销与时间戳状态；
- 使用了哪个信任列表，以及签名者是否命中该列表；
- 哪些 assertion 由签名者创建，哪些只是收集而来；
- 文件在凭证记录中声明经历了哪些操作；
- 签名后造成资产绑定或签名校验失败的改动。

它不能单独确认：

- 画面中的现实事件是真的；
- 签名者的所有陈述都正确；
- 凭证记录一定完整；
- 没有凭证的内容就是假的。

它也不能发现签名前的摆拍、错误陈述、未披露编辑或历史缺口。重新签名可以形成新的有效链，但不自动补齐更早历史。

输出时分别写“凭证状态”和“事实核验结论”。

## 4. AI 检测器

- 检测器结果只能作为弱线索，不能单独作为最终结论；
- 记录工具、版本、阈值、输入版本和已知误报限制；
- 压缩、裁剪、翻拍、字幕和转码会改变检测结果；
- 优先来源链、原始文件、可重复的取证步骤和独立现场证据。

## 5. 输出补充字段

```yaml
media_claims:
  origin:
    verdict: ""
    evidence: []
  edit_or_generation:
    verdict: ""
    evidence: []
  depicted_event:
    verdict: ""
    evidence: []
  caption_context:
    verdict: ""
    evidence: []
provenance:
  tool_and_version: ""
  manifest_present: ""
  asset_binding: ""
  signature_status: ""
  certificate_chain: ""
  trust_list: ""
  revocation_status: ""
  timestamp_status: ""
  signer: ""
  created_assertions: []
  gathered_assertions: []
  manifest_or_claim_id: ""
  validation_results: []
  completeness_limits: ""
```

若无法获得原始文件，只能核验平台重编码版本，必须明确降低把握度。

单点答复也必须给两个结论：

1. **凭证状态**：有效 / 无效 / 缺失 / 不完整 / 无法验证；
2. **事件事实**：支持 / 不支持 / 部分支持 / 证据冲突 / 证据不足 / 不可核验。

凭证缺失或校验失败也不自动证明内容虚假；平台转码、截图、元数据剥离和工具不兼容都可能导致无法验证。
