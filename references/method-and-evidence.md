# 声明、证据与结论方法

本文件用于需要更细拆解、来源评估或争议证据判断的任务。核心原则是“以声明为中心、以证据关系为单位”，不是给整篇文章或整个网站贴永久标签。

## 1. 什么值得核验

### 可直接核验

- 某事件是否发生、何时发生、由谁实施；
- 某数字、比例、排名、金额、增长率或统计趋势；
- 某人是否说过一句话；
- 某法律、标准、产品或政策当前是否有效；
- 某研究是否得出特定结论；
- 某图片或视频的来源、时间、地点、修改历史及其所描绘事件；
- 某引用是否真实存在并支持正文结论。

### 先改写再核验

- “A 比 B 更好” → “按哪个指标、在哪个时间与对象范围内，A 的值高于 B？”
- “X 导致 Y” → 分成时间先后、相关性、机制、混杂因素和替代解释。
- “大多数用户喜欢” → 明确总体、样本、问题、选项、调查时间与“大多数”阈值。
- “官方已经确认” → 明确哪个机构、何时、通过什么正式载体确认了什么。
- “最新研究证明” → 明确研究、发布日期、研究设计、对象与真实结论强度。

### 归因与底层事实分层

下面两条不能合并：

- “公司新闻稿称销量增长 40%”；
- “销量实际增长 40%”。

原新闻稿可以充分支持第一条，却可能不足以支持第二条。相同规则适用于“某官员说”“某论文报告”“某平台显示”等表述。

核验者为判断原话而提出的必要条件，例如“需要 A/B 同期同口径数据”，应记录为 `verification_requirements`，不是新增一条“原文声称 A/B 同口径”的声明。

### 不应强行核验

- 纯偏好：“这个设计很漂亮”；
- 规范判断：“公司应该更激进”；
- 无观察条件的预测：“它一定会成功”；
- 定义不清且无法在当前上下文合理补足的表述。

可以核验这些表述引用的事实前提，但必须把“事实核验”和“价值判断”分开。

## 2. 原子化规则

1. 保留原话，避免拆分后改变含义。
2. 一条原子声明只包含一个主要谓词。
3. 把时间、地域、人群、单位、比较基准和来源归属写入声明。
4. 将“事实 + 解释 + 结论”拆开。
5. 将“存在”“不存在”“全部”“首次”“唯一”等全称或存在性词语单独标注，因为其证据要求更高。
6. 将引用文本与“引用者对文本的解释”拆成两条。

原子化不是越细越好。拆得过细会丢失关系、引入原文没有的问题并扩大检索噪声。完成拆分后做一次覆盖检查：

- 原文中的量词、否定、因果、比较和限定条件是否仍然存在；
- 每个子声明能否回指原文跨度；
- 子声明合起来是否仍回答用户真正关心的问题；
- 因果、趋势或比较关系是否被保留为独立待核对象。

示例：

> “2026 年 A 产品销量增长 40%，超过 B，成为中国第一。”

拆为：

- A 产品 2026 年销量较指定基期增长 40%；
- A 在该区间销量超过 B；
- A 在定义明确的中国市场竞争集合中排名第一。

核验所需条件另记：

- A/B 使用相同的销量定义、统计区间和市场范围；
- 排名覆盖完整且适用的竞争集合。

## 3. 证据发现：SIFT 与横向阅读

把 SIFT 当成搜索动作，不当成评分公式：

1. **Stop**：先停下，确认原话、已知信息、当前情绪或预设结论。
2. **Investigate the source**：离开当前页面，了解发布者、作者、责任主体、专业接近性和利益关系。
3. **Find better coverage**：寻找更接近原始记录、方法更透明或更能处理该问题的来源。
4. **Trace to the original**：把引文、数字、图片和视频追到原始语境。

横向阅读优先于只在一个页面内部寻找“关于我们”或自我声明。当前页面的信息仍可作为线索，但不应成为其自身可信度的唯一证明。

## 4. 来源不是固定等级

同一来源对不同声明的适用性不同：

- 公司财报适合证明公司报告了什么、按何种会计口径披露了什么；
- 它不自动适合证明全行业趋势或产品效果优于竞争者；
- 监管机构原文适合证明规则文本、发布日期和生效状态；
- 新闻报道可能适合确认公开事件，但若只是转述一份公告，证据源头仍是公告；
- 论文适合证明研究设计与结果，不自动证明结果能推广到其他人群；
- 当事人证词接近事件，但仍可能存在记忆、利益和视角限制。

使用以下问题定性评估来源：

| 维度 | 要问的问题 |
|---|---|
| 身份 | 发布者和作者是谁，责任归属是否清楚？ |
| 接近性 | 它如何知道这件事，是记录者、观察者、研究者还是转述者？ |
| 可审计性 | 原始数据、方法、版本、样本和定义是否可见？ |
| 适配性 | 时间、地域、人群、单位和口径是否匹配声明？ |
| 独立性 | 是否与其他来源共享同一原始材料、作者、资金或通讯稿？ |
| 动机 | 有何商业、政治、法律、声誉或选择性披露动机？ |
| 反证 | 是否存在同等或更强的反向证据？ |

CRAAP 的 Currency、Relevance、Authority、Accuracy、Purpose 可以作为提问提示，但不要把不同领域压成一个固定分数。

## 5. 独立性与证据链

### 不应重复计数

- 十家媒体转载同一通讯稿；
- 多篇文章都引用同一个数据集；
- 同一研究团队对同一数据的多篇摘要；
- 不同域名下的同集团内容；
- 搜索摘要与被摘要页面；
- AI 回答与它引用的原始页面。

用“共同源组”记录证据来源。例如：

```text
共同源组 G1：主管机关数据库
├── 主管机关原始表
├── 新闻 A 对该表的报道
└── 博客 B 对新闻 A 的转述
```

这三项能够帮助理解传播，但对原始数值通常只构成一个证据源。

### 什么时候需要多源

- 一个主管机关正式文本通常足以证明该文本写了什么；
- 一个可审计数据库的单条记录可能足以证明该记录存在；
- 市场规模、因果效果、趋势、排名、民意和风险判断通常需要独立方法或视角；
- 高风险结论即使有权威原文，也可能需要专业解释和适用性复核。

“三角验证”应尽量增加证据的独立方法、不同角色或不同数据，而不是简单增加链接。

## 6. 数字与统计核验

逐项记录：

1. 精确数值与单位；
2. 分子、分母和总体；
3. 统计区间与发布日期；
4. 地域与适用人群；
5. 数据是测量、申报、估算、预测还是模型输出；
6. 名义值/实际值、含税/未税、去重/未去重等口径；
7. 同比、环比、复合增长率或绝对变化的计算方法；
8. 原始表格、字段、页码或数据行；
9. 修订、季调、四舍五入和版本差异。

需要推导时展示公式。例如：

```text
同比增长率 = (本期值 - 上年同期值) / 上年同期值
```

不要使用通用的“误差小于 5% 即一致”或“差异小于 10% 即匹配”。容差必须来自统计口径、舍入规则或用户给定标准。

### 图表、表格与版面映射

PDF、图片和演示文稿的文本层经常按内部对象顺序抽取，而不是按读者看到的空间顺序排列。核验图表或复杂表格时：

1. 先保存图表标题、页码、分类、数值、图例、单位和条件分母；
2. 查看渲染页或能保留坐标的结构，确认每个数值究竟对应哪个标签、系列、列和层级表头；
3. 用合计、排序、单位、正文解释和重复出现的同一图表交叉检查映射；
4. 记录最终映射，不只抄写一串脱离标签的数字；
5. OCR、文本抽取和视觉版面不一致时，保留冲突并降低把握度；无法确定就标为证据不足，不按抽取文本的先后顺序猜测。

例如，文本层依次出现 `53% 29% 15%`，随后才出现多个分类标签时，不能默认前三个数字对应前三个标签。必须回到原始版面确认空间关系。

## 7. 因果与比较声明

### 因果

至少检查：

- 时间先后是否成立；
- 证据只是相关还是有识别因果的设计；
- 是否有对照、随机化、自然实验或合理反事实；
- 是否存在关键混杂因素；
- 效果是否在研究范围之外被外推；
- 原作者使用的是“相关”“可能”“导致”中的哪一种强度。

### 比较与排名

至少检查：

- 比较对象是否来自同一集合；
- 指标、单位、时间和数据源是否一致；
- “第一”“最大”“领先”是否遗漏了市场、渠道或产品类别限定；
- 排名是观察值、模型估算还是商业榜单；
- 是否只挑选有利指标。

## 8. URL、引文与时间状态

### URL

分别记录：

- 可访问 / 访问受限 / 失效 / 已重定向；
- 页面身份是否与引用一致；
- 当前版本是否包含被引用内容；
- 页面内容是否真正支持声明；
- 是否存在存档、版本记录或更稳定的原始链接。

HTTP 200 只说明请求成功；403 只说明当前访问受限。两者都不能直接决定声明真假。

### 引文

- 优先完整文本、正式逐字稿或原始音视频；
- 核对说话人、时间、删节、上下文和翻译；
- 区分“原话存在”与“原话所述事实正确”；
- 无法取得完整上下文时降低把握度。

### 时间

区分：

- 声明在当时是否有依据；
- 声明现在是否仍然有效；
- 来源是在事件前、事件后还是经修订后发布；
- 用户要求的资料截止日期。

已过时不一定意味着当时错误。输出中应明确“截至何日”的结论。

核验历史声明时，后来的材料可以帮助发现真相，但必须区分：

- 声明发表当时可获得的证据；
- 后来出现、用于回顾性判断的证据；
- 当前仍然有效的状态。

## 9. 结论校准

### 支持

- 证据直接针对同一原子声明；
- 关键口径匹配；
- 没有未解释的强反证；
- 结论强度不超过来源。

### 不支持

- 可靠原始材料直接相反；
- 数值、身份、时间或引文归属明确错误；
- 声称的来源中不存在该内容，且有足够证据确认不是版本或访问问题。

### 部分支持

- 复合声明中只有部分必要子声明获得支持；
- 归因声明成立，但底层事实尚未得到支持；
- 来源只支持原句中的较弱部分。

“误导”属于单独的表达风险。即使底层事实证据不足或全部正确，伪多源、截断引文、过时表述、口径替换、从局部外推总体或把相关性写成因果，仍可能构成表达风险。

### 证据冲突

- 高质量来源使用相近口径却得出实质不同结果；
- 差异无法由时间、定义、样本、修订或方法解释。

### 证据不足

- 只有声明者自报且缺少可审计依据；
- 原始数据不可访问；
- 搜索只能找到循环引用；
- 找不到证据，但尚不能证明不存在。

### 不可核验

- 主要是价值判断或不可观察预测；
- 关键术语没有可操作定义；
- 声明缺少决定性上下文且无法合理恢复。

## 10. 复合声明聚合

1. 保存父声明的逻辑结构：合取、析取、比较、因果或推论。
2. 展示所有必要子声明与证据条件。
3. 不对标签做投票、平均或百分制换算。
4. 对合取句，全部必要子声明获支持才能支持整句。
5. 对因果句，仅核实原因和结果分别发生，仍不足以支持因果关系。
6. 子声明证据不足时，父声明最多只能“部分支持”或“证据不足”，不能因其他部分正确而整体通过。
7. 将表达风险单列，不用它替代事实证据标签。

## 11. 常见失败方式

- 先相信一个结论，再只搜支持它的关键词；
- 把来源名气当作对所有主题都适用；
- 把多条转载当成交叉验证；
- 把“没搜到”写成“不存在”；
- 只看摘要，不打开原文；
- 只看论文结论，不看研究对象与限制；
- 用一个固定时效阈值处理法律、历史、技术规格和新闻；
- 用单一 AI 检测器判断图片、文本或视频真假；
- 给整份报告一个漂亮但不可校准的百分制分数；
- 把“来源有偏见”直接等同于“其中每条事实都错误”。
